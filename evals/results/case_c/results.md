## Method

Cases C were each run under three memory arms through the API (`POST /incidents`, `POST /incidents/{id}/runs?memory=<arm>`, then `GET /runs/{id}` and `/events`), 2 time(s) per case and arm (N=2). **off**: no memory in the prompt. **placebo**: one unrelated memory (other bug types, `evals/placebo_memories.json`) injected by the loop through the same prompt block as a real memory, length-matched (each length ratio to the real memory between 0.85 and 1.15, table below). **real**: normal recall, with only case A's Earn memory in the database, proven by the real runner and promoted by the memory service (`scripts/seed_demo.earn`). Isolation: each run used its own throwaway Atlas database (`traceback_eval_<stamp>_<case>_<arm>_<n>`, set up with `scripts/atlas_setup.py`, run in its own process with `MONGODB_DB` set to it, dropped afterwards), so no run's memory renewals, disputes or promotions reached another run, and the demo and team databases were not touched. Model: claude-sonnet-5-5; prompt system_v1; budget 8 tool calls, 2 fix attempts, 120 s for every run. Code revision `cbc2926`, fixture tree `ff40df4`, trusted tests `a6fe0ce`, no uncommitted changes to fixtures, tests, cases, agent or runner. Scored against `cases/<id>/labels.json` from the runner's verification events only. Counts are over valid runs; INVALID (the arm's condition did not hold, e.g. placebo not injected) and ERROR (no agent behaviour to score) runs are listed but never counted. Raw counts only: with this N, no rates or significance are claimed.
